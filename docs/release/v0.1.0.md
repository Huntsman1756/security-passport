# Release report — v0.1.0

## What shipped

A functional, evidence-backed operational passport for European
instruments:

- **CLI** — `security-passport <ISIN>` + `--json`, `--sources`,
  `--explain`, `update`, `validate`, `status`, `doctor`.
- **REST API** — read-only, `/api/v1/passports/{isin}`, evidence
  and sources projections, search, status, health. ETag-stable
  per generation; one request = one pinned generation.
- **Web SPA** — React + TanStack Query. Five blocks, per-field
  status chips, provenance drawer (source, rule, raw value,
  alternatives, temporal basis), document graph, listings table,
  dark/light mode, explicit `not_found` rendering.
- **Data pipeline** — own-source ingest (ECB eligible assets,
  ECB SSS/links, PRIII, MIC) → parquet/json stores → manifest +
  semantic fingerprint → atomic `CURRENT` publish. Staging and
  serving never mix.
- **Provider port** — `InstrumentProvider` (OpenInstrument API in
  prod, fixtures in tests) + `PassportStore` (generated stores or
  fixture replay). Same mapping logic live and offline.

## Verified contracts

- ISIN validation rejects bad check digits (`DE000A3LJCB0` → 422).
- ECB absence derives `eligible=false` only within the snapshot,
  with the snapshot id attached and the limitation stated.
- ES prefix never infers Iberclear: `ES0113900J37` renders
  `not_found`, `ES0000101966` renders `reported` because ECB
  `CLES01` is instrument-level evidence.
- Conflict in `IE0007SRI1C7` issuer LEI is preserved with both
  alternatives and per-assertion evidence.
- PRIII `normalize_raw` is used identically by live fetch, update
  pipeline, and fixture replay — one normalization path.
- Idempotent update: identical inputs publish different
  `generation-XXXX` names with the **same**
  `semantic_fingerprint`.
- Deterministic build: two identical builds produce identical
  passport JSON (volatile `generated_at` excluded).

## Known limitations (v0.1)

- Settlement paths are never asserted; only issuer-SSS identity
  and Eurosystem link topology are shown as context.
- No `--as-of` query — FIRDS history is reconstructed upstream and
  left-censored; exposing time-travel without full temporal
  semantics would violate the honesty contract.
- `data/raw/` currently stores normalized own-source payloads;
  byte-immutable artifact registry is a post-v0.1 gap (upstream
  `openinstrument/artifacts/` is the reference implementation).
- Upstream `/v1/evidence/{isin}` is snapshot-sensitive
  (hardcoded `snapshot=2026-09-12` vs generation `2026-10-03`);
  fixture capture tolerates the 503 upstream bug.
- No auth/rate limiting — designed for public read access behind
  an edge; add throttling at Caddy/infra before public exposure.
