# v0.1.2 — POST-TRADE model hardening

## What changed

POST-TRADE was re-modelled so four assertions that must never
merge stay separate:

| before (v0.1.1) | after (v0.1.2) |
|---|---|
| `issuer_sss` field | `issuer_csd` field — ECB `ISSUER_CSD` with `scope: eurosystem_collateral_reference` |
| `csd_admission` field + `instrument_csd_evidence` collection | `settlement_locations` collection + `settlement_location_count` field — multi-valued, `source_published_at` vs `effective_from` |
| `relevant_links` collection | `link_topology` collection — `link_type`, context only |
| `possible_paths` field | `route_assessments` collection — `inferred`/`not_assessable`, rule + limitations |

This is a breaking change to the passport payload (fields are an
open map — OpenAPI schema unchanged, oasdiff gate passes; no
published consumers).

## Instrument-level settlement evidence

Euronext Securities Milan workbook now parsed full-width: issuer
CSD, current place, designated place (**effective 2026-09-21**,
the European CSD Offering go-live), and up-to-N alternative
settlement systems. The file's own publication date
(2026-09-18) and its effective date stay separate — the
publication≠effective golden is `FR0000120271` /
`IE00B4L5Y983` (3 and 4 locations respectively).

Second file from the same docs page added: `euronext_frs`
(French registered shares + issuer CSD).

Probed and classified, not ingested:

- `euronext_porto_custody` — ISIN-filterable page is
  `PUBLIC_HUMAN_LOOKUP`; its CSV endpoint 404s. No crawler.
- `clearstream_eligible` — `PREMIUM`.
- `euroclear_isin_lookup` — `AUTH_REQUIRED`.

Source registry gained the access taxonomy and the hard rule:
`AUTH_REQUIRED` / `PREMIUM` / `BLOCKED_POLICY` →
`PROBED_RESTRICTED`, never silently scraped.

## Venue context (secondary market)

Listings now carry `operating_mic`, `oprt_sgmt`, `operator`,
`operator_lei`, `market_category` from the same official ISO
10383 registry OpenVenue wraps — segment vs operating venue
distinguished without a second resolution engine. OpenVenue's
rulebook corpus and operational dossier remain the v0.2
integration behind `VenueContextProvider`; verified its
`/venues/{mic}` contract live against the local service.

## Fund roles (cnmv_iic)

`primary_market` now carries `fund_vehicle`, `fund_share_class`,
`management_company`, `depositary` + a `fund_roles` collection
for ES IIC share classes — wrapped from the OpenFunds upstream
dataset (`OPENFUNDS_DATASET` → `stores/fund_roles.json`,
`upstream_artifact_reference`). Gestora/depositario are roles,
never issuer identifiers → no false role-vs-issuer LEI
conflicts. New golden: `ES0105321030` (32 goldens total).

emisiones-es audited again and stays deferred: its document
graph is not yet a stable machine-readable bundle.

## Status taxonomy hardened

`route_assessments` now separates epistemology (`status` ∈
closed `FieldStatus`) from verdict (`assessment` ∈
{`not_assessable`, `topology_only`}). New test scans every
status in every passport recursively — no provider can invent a
status.
